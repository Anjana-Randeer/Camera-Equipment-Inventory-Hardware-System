# \# 📸 Camera Equipment \& Inventory Hardware System

# 

# This project is a dedicated web-based application designed to manage and track camera equipment for studios and rental services. It provides a structured tracking system to register equipment, monitor physical locations, log check-outs and check-ins, and record maintenance history. The system was developed as a Group Project for the CSC 2032 Object Oriented Programming module at the University of Sri Jayewardenepura.

# \## 🚀 Key Features

# 

# \* \*\*Admin Controls\*\*: Administrators can manage the overall system and oversee inventory health. They are authorized to add or remove equipment, manage user accounts, and view all reports.

# \* \*\*Staff Workflows\*\*: Staff members handle day-to-day equipment handling. They can check equipment in and out, log damage and maintenance, and search the inventory.

# \* \*\*Automated Tracking\*\*: The application accurately tracks where a piece of equipment is, who has it, its current condition, and whether it is overdue for return or scheduled maintenance.

# 

# \## 🛠️ Technology Stack

# 

# \* \*\*Frontend\*\*: HTML, CSS, and JavaScript pages served by JSP.

# \* \*\*Backend\*\*: Java classes running on Apache Tomcat via Servlets, utilizing the Spring Boot framework.

# \* \*\*Database\*\*: MySQL is used for storing all persistent data including equipment, users, categories, and maintenance records.

# \* \*\*Libraries\*\*: Utilizes the Lombok library (specifically the `@Data` annotation) for automatic encapsulation.

# 

# \## 📐 Object-Oriented Design

# 

# The system implements core OOP principles to model real-world inventory concerns:

# \* \*\*Encapsulation\*\*: Class fields (such as those in `User` and `MaintenanceRecord`) are kept secure by declaring them as private. Data is accessed safely using public getters and setters generated by Lombok.

# \* \*\*Inheritance\*\*: A parent-child class hierarchy prevents code duplication. The `Equipment` class acts as the base parent, while specific child classes like `CameraBody`, `CameraLens`, and `Accessories` inherit common properties and add unique attributes.

# \* \*\*Polymorphism\*\*: Objects of different subclasses can be treated as objects of a common superclass. Different objects are assigned to a generic `Equipment` variable and saved using a single repository method.

# \* \*\*Abstraction\*\*: Complex background logic is hidden from the presentation layer using interfaces. The Controller interacts only with the `EquipmentService` interface, remaining unaware of complex database operations.

# 

# \## 🏗️ System Architecture

# 

# The application follows a layered architecture to ensure maintainability and a strict separation of concerns:

# \* \*\*Controller Layer\*\*: Handles HTTP requests using interface-based abstraction.

# \* \*\*Service Layer\*\*: Contains the core business logic, separating definitions from implementations.

# \* \*\*Repository Layer\*\*: Manages database operations.

# \* \*\*Entity Layer\*\*: Contains the database models and the OOP class hierarchy.
